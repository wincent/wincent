Creates symlinks from the `$HOME` directory to the dotfiles in this repo.

## Sandbox configuration

`sb` loads its built-in defaults, then an optional host-side Bash file named by `SB_BASE_CONFIG`, then the selected project configuration. Project selection is unchanged: a project-local `.sandboxrc` takes precedence over the first matching `sandboxrc` under `SB_CONFIG_PATH`. Derived values such as the guest repository path are calculated after both files are loaded.

Export `SB_BASE_CONFIG` from your machine-specific shell configuration to share defaults across projects without putting private setup in this repository or the base VM image. Unset or empty means no base configuration; an explicitly configured missing, unreadable, or invalid file stops the command. Configuration files run on the host and are trusted shell code. They can use `sb_ssh` and `sb_scp`; keep provisioning side effects inside `sb_provision`, because configuration is sourced for every command.

Project values override base values. Arrays replace earlier arrays unless explicitly appended with `+=`. A project-defined `sb_provision()` replaces the base function rather than chaining it; otherwise the base function is inherited. A project can use `unset -f sb_provision` to disable an inherited hook. The final hook receives the VM IP and runs once during create/reset, after SSH key and Git identity setup, not on connection. Existing VMs are not updated automatically.

## Private proxy routes

The Pi nono profile can include private credential routes without putting service names, hosts, or authentication commands in this repository. Export `NONO_PROXY_CONFIG` from your private shell configuration, pointing to a JSON file with two optional maps:

- `credentials`: additional named nono `custom_credentials`, automatically activated in the profile's `network.credentials` list. Built-in route names cannot be replaced.
- `capture`: nono `credential_capture` definitions for routes using `cmd://` credentials. Commands run on the host, not in the sandbox.

The file uses nono's configuration fields directly. Store credential references and capture commands, not actual secrets. Whole-string `$NAME` values are replaced with inherited environment variables at install time, including strings in command argument arrays; there is no shell evaluation or recursive expansion. Missing referenced variables and malformed configuration fail installation without dumping the private file.

If the export or file is absent, the additional routes are omitted. On a new machine, load the private configuration and rerun `./install dotfiles` when ready. Installation renders the profile with mode `0600` and derives phantom environment exports from the resulting routes, including for VM clients. Validate with `nono profile validate pi`; start a new session to pick up profile changes. The wrappers select a matching proxy generation automatically.

## Proxy lifecycle

`bin/pi` uses nono's session-specific sandbox proxy. On macOS, `bin/pi-naked` and `sb ssh` lease a standalone proxy generation matching the installed configuration. Python 3's standard library provides locking and process management; concurrent launches serialize selection/startup and reuse a matching healthy generation. The fingerprint follows selected authored dependencies, including canonical symlink targets, external transitive parents, installed pack profiles/manifests, resolved settings, the nono binary, relevant environment values, CA/auth files, and generated exports. Unrelated profiles do not invalidate reuse. `nono profile show --json` alone is insufficient because it omits custom credentials and capture commands.

A changed fingerprint starts a separate loopback proxy on an OS-assigned port. Each generation retains private profile/CA/auth/export snapshots. Selected authored JSON(C) profiles are mirrored with canonical source identities and explicit links for resolved user-parent lookups. This preserves sibling precedence and transitive inheritance through external symlinks. Packs retain native loading/verification, with their raw dependencies fingerprinted before and after startup. Resolved settings are also compared before startup, and installed configuration is checked again after startup before publication. Existing clients keep their old policy and exports, while new clients get the updated configuration. Startup failure or configuration changing during startup never silently falls back to an old proxy. Expired installed CAs fail with an instruction to rerun installation. The host proxy and capture helpers always run from `$HOME`, with `PWD` and relative `PATH` entries anchored there; launching Pi from another repository cannot silently reuse a helper running from the previous repository.

Leases track the client PID and start time, surviving `exec` into Pi or SSH. Later launches and `nono-proxy gc` stop unleased generations and remove their snapshots. SSH sessions use separate guest reverse-forward ports and generation-specific certificate paths, and fail if the required credential-proxy forward cannot be established. Optional development-port and socket forwards are added afterward through the foreground SSH connection's control socket; collisions warn without aborting the session or its required proxy tunnel. The control master does not persist beyond that SSH session. A VM lease lasts for the SSH connection, not detached guest processes; a new SSH connection supplies new proxy exports. Closing a client does not immediately reap its proxy; collection runs at the next launch or explicit `gc`.

`nono-proxy status` lists generations. `nono-proxy stop` explicitly stops all managed and recognized legacy proxies, interrupting their clients. Manual `nono-proxy start` or `eval "$(nono-proxy env)"` pins a generation until explicit stop because those clients have no tracked lifetime. Pre-generation proxies are also retained until explicit stop; automatic cleanup never guesses whether their clients are idle.

For scripted clients, `nono-proxy acquire PID` returns an identifier. Pass it to every subsequent call with `--generation ID` (`env`, `ca`, `port`, or `guest-env`) so configuration updates cannot mix results from different generations. VM callers additionally provide `--guest-port PORT` to `guest-env`. `--generation ID lease-dir PID` allocates a private, short-path scratch directory for a live lease (used for SSH control sockets); it is collected with the lease. Logs and state directories are private: proxy logs can contain the local proxy password.
